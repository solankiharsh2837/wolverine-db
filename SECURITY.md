# Security policy

Report suspected vulnerabilities privately to the project maintainers through the security contact published with each release. Do not open a public issue for an exploitable flaw, secret exposure, integrity bypass, recovery bypass, or protocol ambiguity with security impact.

Include affected version, reproduction steps, impact, and any suggested mitigation. Maintainers will acknowledge reports, assess severity, coordinate remediation, and publish an advisory after a fix is available. No response-time guarantee is made by this initial specification repository.

WolverineDB detects specified classes of tampering; it does not establish intent, prevent a fully compromised trusted environment from fabricating new authorized-looking history, or replace access control, backups, monitoring, or incident response.

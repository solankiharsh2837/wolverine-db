# WolverineDB v0.7 Threat Model: Interleaved Adversarial Mutations

WolverineDB v0.7 expands the threat model to account for sophisticated attackers who interleave malicious operations with genuine application transactions over hours or days.

## Threat Taxonomy & Mitigations

| Threat Vector | Adversarial Action | Wolverine v0.7 Mitigation |
| :--- | :--- | :--- |
| **Interleaved Poisoning** | Attacker inserts malicious rows while genuine users continue updating database. | Dual-dimension classifier isolates attacker mutations while preserving verified user transactions. |
| **Causal Hijacking** | Legitimate user transaction depends on data injected by attacker. | Dependency Graph marks transaction `DEPENDENCY_BLOCKED` to prevent corrupt state materialization. |
| **Hash-Chain Fracturing** | Attacker tampers with historical change hash to hide prior fraud. | Fractures contiguous frontier at tampering point; subsequent transactions require independent proof graph paths. |
| **Competing Branch Injection** | Attacker forks history to introduce conflicting row updates. | Detected as `STATE_CONFLICT`; fails closed and requires explicit multi-party Ed25519 resolution. |
| **Metadata Tampering** | Attacker attempts to modify local classification decisions or graph digests. | Cryptographically committed `reconstructionGraphDigest` and `dependencyGraphDigest` prevent metadata tampering. |

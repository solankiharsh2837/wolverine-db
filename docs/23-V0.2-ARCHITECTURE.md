# WolverineDB v0.2 Architecture: External Evidence & Native PostgreSQL Capture

WolverineDB v0.2 represents the second-generation architecture for cryptographic database integrity, introducing externalized trust boundaries and native PostgreSQL Write-Ahead Log (WAL) logical decoding capture.

## High-Level Architecture

```
POSTGRESQL
    │
    ┌──────────┴──────────┐
    │                     │
    ▼                     ▼
SQL/Triggers        PostgreSQL WAL
    │                     │
    └──────────┬──────────┘
               ▼
       WOLVERINE CAPTURE
               │
               ▼
        Canonical CHANGE
               │
               ▼
         SHA-256 CHAIN
               │
               ▼
       MERKLE CHECKPOINT
               │
        ┌───────┴────────┐
        ▼                ▼
   PostgreSQL      External Store
    metadata         S3 / WORM
                         │
                         ▼
                 CHECKPOINT ANCHOR
```

## Architectural Principles

1. **Externalized Trust**: The database is no longer the sole repository for proof material. Checkpoints containing state Merkle roots and change chain heads are anchored to independent, tamper-resistant external stores (Local, S3 Object Lock, WORM).
2. **Dual-Capture Capability**: Both trigger-based capture and logical WAL decoding feed into a unified Capture Normalizer, producing identical canonical change streams.
3. **Immutability of Core Protocol**: The v0.1.0 protocol (`WDB-0001` through `WDB-0006`) remains the immutable cryptographic foundation. v0.2 builds an external trust envelope around it.
4. **First-Class Recovery Lineage**: Recovery is treated as a continuous, cryptographically bound provenance chain rather than an unlinked post-incident procedure.

# WolverineDB v0.6 Threat Model: Federated Zero-Trust Security

This document outlines the adversarial model and defense matrix for federated multi-node deployments.

## Adversarial Scenarios & Mitigations

| Adversarial Attack | Attack Scenario | Federated Trust Mitigation |
| :--- | :--- | :--- |
| **Forged Security Event** | Attacker injects fake alert to trigger panic | Signature verification against node Ed25519 identity key (`WDB-0051`) fails. |
| **Event Replay Attack** | Attacker replays old legitimate event | Monotonic `nodeSequence` and `previousEventHash` continuity check rejects replayed sequence. |
| **Byzantine Node Compromise** | 1 node is compromised and reports corrupt state | $M$-of-$N$ Federated Checkpoint Consensus isolates minority; node is placed in `QUARANTINED`. |
| **Federation Network Partition** | Network split leaves 2 nodes in Region A and 3 in Region B | Threshold quorum ($M=4$) fails closed rather than allowing divergent state forks. |
| **Recovery Hijacking** | Compromised application node requests unauthorized restore | Federated Quorum requires independent multi-node signatures; proposing node cannot sign. |
